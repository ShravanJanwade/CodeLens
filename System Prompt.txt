ROOT CAUSE ANALYSIS
===================

Do not let the LLM invent evidence.

Example:

ROOT CAUSE

Payment service v1.8.3 introduced a database connection leak.

Evidence:

1. DB connection usage increased from 41% to 96%.
2. Error rate increased 47 seconds after deployment.
3. 86% of failing requests include the payment repository call.
4. v1.8.2 shows normal connection utilization.
5. Restarting the payment service restores connection utilization.

Confidence: 91%

Use evidence-backed reasoning.

==================================================
IMPORTANT AI ENGINEERING PRINCIPLES
===================================

Do NOT build "AI magic".

The architecture should follow:

Tools provide evidence.
Deterministic systems compute facts.
The LLM reasons over evidence.
The orchestrator controls workflow.
Humans control dangerous mutations.

The LLM must not be the source of truth for:

metrics
logs
deployment state
service state
incident state

Those come from actual systems.

This flow must work end-to-end before optional features are prioritized.

The entire project must be designed and implemented so that I can build, run, test, deploy, and publicly demo it without receiving ANY BILL.

Target cost: $0/month.

Do NOT choose a service merely because it has a "free tier."

A service is acceptable ONLY if:

1. The required functionality can remain within its permanent free allowance for this project.
2. The project does not require upgrading to a paid plan.
3. The project does not require paid credits.
4. The project does not require a paid subscription.
5. The project does not depend on a free trial.
6. The project does not require a paid domain.
7. The project does not require a credit card for the core setup where avoidable.

==================================================
BILLING SAFETY
==============

Where the platform supports usage limits, configure conservative limits.

Examples:

* request limits
* rate limits
* maximum repository size
* maximum analysis size
* maximum incident replay frequency
* maximum telemetry volume
* maximum retention
* maximum agent execution steps
* maximum file count
* maximum API requests

The application should fail safely rather than generating unexpected resource consumption.

For example:

MAX_REPOSITORY_SIZE = 25 MB

MAX_FILES_PER_ANALYSIS = 500

MAX_AGENT_STEPS = 25

MAX_TOOL_CALLS_PER_RUN = 30

MAX_TELEMETRY_EVENTS_PER_MINUTE = 500

These limits are for cost and reliability protection.

Make them configurable.
